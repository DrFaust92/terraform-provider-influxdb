# influxdb_user (Resource)

Manages an InfluxDB user and its database privileges.

## Example Usage

```terraform
resource "influxdb_database" "green" {
  name = "terraform-green"
}

resource "influxdb_user" "paul" {
  name     = "paul"
  password = var.paul_password

  grant {
    database  = influxdb_database.green.name
    privilege = "WRITE"
  }
}

# Keep the password out of state (Terraform 1.11+). Bump
# password_wo_version to apply a new password_wo.
resource "influxdb_user" "ringo" {
  name                = "ringo"
  password_wo         = var.ringo_password
  password_wo_version = "1"
}
```

~> **Upgrading from 1.x:** 1.x releases stored a SHA-256 hash of `password` in state. The first plan
after upgrading shows an in-place update of `password`; applying it only replaces the hash with the
password in state and does not change the password on the server.

## Schema

### Required

- `name` (String) Name of the user.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `admin` (Boolean) Whether the user has all privileges (is an admin).
- `grant` (Block Set) Privileges of the user on databases. (see [below for nested schema](#nestedblock--grant))
- `password` (String, Sensitive) Password of the user. Changing it re-creates the user; use `password_wo` to rotate the password in place. Exactly one of `password` and `password_wo` must be set.
- `password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Write-only alternative to `password`, never stored in state. Requires Terraform 1.11 or later.
- `password_wo_version` (String) Change this value to update `password_wo`, Terraform cannot detect changes to write-only attributes.

### Read-Only

- `id` (String) The user name.

- `privilege` (String) One of `READ`, `WRITE` or `ALL`.
